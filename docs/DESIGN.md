# 오늘 점심 지도 — 디자인 가이드 (DESIGN)

작성 2026-11-19 · 상태: **초안** · 기반: [기획서.md](./기획서.md), [SPEC.md](./SPEC.md)

화면을 만들 때 따르는 색·글자·간격·컴포넌트 규칙을 담는다. CLAUDE.md의 "디자인 규칙"은 이 문서의 요약이다. 수치는 현재 코드(`src/app/globals.css`, `src/lib/menus.ts`, `src/components/*`)를 읽고 정했고, 코드와 다른 부분은 §8에 모았다.

> **기획 변경 포함**: 지도를 "칸마다 1위 메뉴 색"에서 **"메뉴 하나를 골라 동네별 진하기로 보기"** 로 바꾼다 (§5.5). 기획서 §지도표현, SPEC §3, `/api/map` 응답도 같이 바뀌어야 한다.

## 0. 방향

> 당근의 동네 말투 + 토스의 단순함 + 당근 계열 주황 한 가지 색의 진하기로 칠한 지도.

로그인 없이 들어와 메뉴 하나 고르고 나가는 서비스다. 화면은 흰색 계열로 조용하게 두고, 색은 지도에서만 쓴다.

## 1. 원칙

1. **색은 지도에만 쓴다.** 버튼·글자·배경은 흰색 계열 무채색이다. 의미가 있는 색은 지도의 당근 계열 주황 진하기 하나뿐이다. CLAUDE.md의 "주색 1개"는 **잉크색(`--fg`)** 이고, 화면마다 제일 중요한 버튼 하나만 잉크색으로 채운다.
2. **한 화면에 결정 하나.** 홈은 "메뉴 고르기", 시트는 "이걸로 결정", 지도는 "보기"만 한다.
3. **모바일 375px 기준, 최대 폭 480px.** 지금 코드의 `maxWidth: 480`을 유지한다.
4. **색만으로 구분하지 않는다.** 메뉴는 항상 이름으로 보여준다. 지도 진하기는 범례로 설명하고, 칸을 누르면 숫자로 보여준다.
5. **안심 문구를 보여준다.** 위치를 묻기 전에 "위치는 칸 찾기에만 쓰고 저장하지 않아요"를 보여준다 (기획서 원칙 2).

## 2. 색

### 2.1 UI 토큰 (`globals.css`의 CSS 변수)

| 토큰 | 라이트 | 다크 | 용도 | 상태 |
|---|---|---|---|---|
| `--bg` | `#ffffff` | `#0b0b0c` | 페이지 배경 | 있음 |
| `--fg` | `#1a1a1a` | `#f3f4f6` | 본문 글자, **주색**(채운 버튼) | 있음 |
| `--muted` | `#6b7280` | `#9ca3af` | 보조 글자 (대비 4.83 / 7.75) | 있음 |
| `--border` | `#e5e7eb` | `#27272a` | 구분선, 버튼 테두리 | 있음 |
| `--surface` | `#ffffff` | `#18181b` | 버튼·시트·카드 배경 (다크에서 배경과 구분) | 신규 |
| `--danger` | `#b42318` | `#f97066` | 오류 문구 (대비 6.57 / 7.06) | 신규 |
| `--overlay` | `rgba(0,0,0,0.4)` | `rgba(0,0,0,0.6)` | 시트 뒤 어둡게 | 신규 |

- 코드에 색 값을 직접 쓰지 않는다. 위 토큰과 §2.2 지도 토큰만 쓴다.
- `--danger`는 문구에만 쓰고, 항상 무엇이 안 됐는지 글로 같이 쓴다.

### 2.2 지도 색 (데이터 색)

진하기 3단계는 당근 계열 주황 한 가지 색이다 (OKLCH 색상각 48°). 다크 모드에서는 순서를 뒤집어서, 적을수록 배경에 가깝고 많을수록 밝게 한다.

| 토큰 | 뜻 | 라이트 | 다크 |
|---|---|---|---|
| `--map-1` | 조금 (1단계) | `#ff9f6d` | `#883c04` |
| `--map-2` | 보통 (2단계) | `#ed6e12` | `#d35f03` |
| `--map-3` | 많이 (3단계) | `#ab4b01` | `#ffa475` |
| `--map-empty` | 표 적음 / 아직 없음 | `#f0f1f3` | `#1f1f23` |
| `--map-stroke` | 칸 경계선 | `rgba(0,0,0,0.25)` | `rgba(255,255,255,0.18)` |

- 3단계는 데이터 시각화 순서형 색 검증을 라이트(`#ffffff` 위)·다크(`#0b0b0c` 위) 모두 통과했다: 한 가지 색, 밝기 순서 유지, 단계 간 밝기 차 0.06 이상, 가장 옅은 단계도 배경 대비 2:1 이상 (2.01 / 2.52).
- 라이트의 `--map-1`은 2.01:1로 기준을 겨우 넘는다. 더 옅게 바꾸면 흰 배경에서 안 보이니 이보다 밝게 하지 않는다.
- 주황은 `--danger`(빨강)와 계열이 가깝다. `--danger`를 지도 화면의 칸·칩에 쓰지 않는 규칙(§2.1)으로 구분한다.
- 투명도로 진하기를 만들지 않는다. 투명도는 배경색에 따라 모드마다 다르게 보인다. 단계마다 정해진 색을 쓴다.

### 2.3 메뉴 색

`src/lib/menus.ts`의 `color`는 **장식**으로만 남긴다. 메뉴 고르기 버튼의 색 점에만 쓴다.

- 지도·지도 화면에서는 쓰지 않는다. 지도 주황과 한식·국밥·탕의 주황을 같은 뜻으로 오해하지 않게 한다.
- 글자색으로 쓰지 않는다. 글자 기준(4.5:1)을 라이트·다크 모두 넘는 메뉴 색이 하나도 없다.
- 이름이 항상 같이 있으니 색끼리 구분이 안 돼도 괜찮다.

**왜 1위 메뉴 색 지도를 버렸나**: 지금 10색을 데이터 시각화 팔레트 검증으로 돌려보면 전부 실패한다. 지도는 어느 칸이든 붙을 수 있어서 모든 색 쌍을 비교해야 한다.
- 색약 기준 아시안–국밥 거리 4.0 (기준 8 이상)
- 일반 시력 기준 중식–한식 거리 7.5 (기준 15 이상)
- 고기·구이는 채도가 낮아 회색으로 보임
- 국밥·면은 너무 밝음

이렇게 모든 칸이 붙는 그림에서 서로 확실히 구분되는 색은 3개 정도가 한계라, 색을 다시 골라도 10개는 통과할 수 없다.

## 3. 글자

- 글꼴은 1종: 시스템 글꼴 (`globals.css`의 `system-ui, -apple-system, …, "Apple SD Gothic Neo", "Noto Sans KR"`). 웹폰트는 넣지 않는다.
- 크기는 5단계만 쓴다. 지금 코드는 11~22px 사이 9가지를 쓰고 있다.

| 단계 | 크기 | 굵기 | 용도 | 지금 코드에서 바꿀 값 |
|---|---|---|---|---|
| 제목 | 24 | 700 | 페이지 제목 | 20, 22 |
| 소제목 | 20 | 700 | 시트 제목, 룰렛 결과 | 17, 20 |
| 본문 | 16 | 400 / 600 | 버튼, 목록 항목 | 15, 16 |
| 보조 | 14 | 400 | 설명, 내 칸 정보 | 13, 14 |
| 작은 글자 | 12 | 400 | 거리, 범례, 기준 날짜 | 11, 12 |

## 4. 간격 · 모서리 · 그림자

- **간격**: 8의 배수 `8 / 16 / 24 / 32 / 40`. 칩 안쪽과 아이콘–글자 사이처럼 좁은 곳에만 `4`를 허용한다. 지금 코드의 3, 5, 6, 10, 14, 20, 28은 가까운 값으로 맞춘다.
- **화면 여백**: 좌우 16, 섹션 사이 24.
- **모서리**: `4` 범례 칸 · `12` 버튼·카드 · `16` 하단 시트 위쪽 · `999` 칩. 지금 코드의 3, 14는 4, 12로 맞춘다.
- **그림자**: 지도 위 떠 있는 카드에만 `0 8px 32px rgba(0,0,0,0.18)`. 다른 곳은 테두리로 구분한다.
- **누르는 영역**: 버튼·목록 항목·칩은 높이 44 이상.

## 5. 컴포넌트

### 5.1 버튼

기본은 흰색 계열 버튼이다. 채운 버튼은 화면마다 1개만 쓴다.

| 종류 | 모양 | 쓰는 곳 |
|---|---|---|
| 기본 버튼 | 배경 `--surface`, 테두리 `--border`, 글자 `--fg`, 16/400, 높이 44 | 룰렛 돌리기, 지도 보기, 메뉴 고르기 |
| 채운 버튼 (주) | 배경 `--fg`, 글자 `--bg`, 16/600, 높이 48 | "이걸로 결정" (시트), "내 위치로 내 칸 찾기" (홈, 칸이 없을 때) |
| 글자 버튼 | 글자 `--muted`, 밑줄, 14 | 다시 찾기, ← 홈 |

- 비활성은 `opacity: 0.5` + 이유를 글로 ("오늘은 이미 결정했어요").
- 버튼 앞 이모지는 1개까지 (📍 🎲 🗺️).
- 이름 주의: 지금 `LunchHome.tsx`의 `primaryBtn`은 기본 버튼이다. 채운 버튼은 `ShopSheet.tsx`의 `decideBtn`이다.

### 5.2 메뉴 고르기 · 메뉴 칩

- **메뉴 고르기** (`MenuPicker`): 기본 버튼 2열 그리드. 안에 지름 10 색 점(§2.3 장식) + `--fg` 글자, 간격 8. 지금 구조와 같고 배경만 `--surface`로 바꾼다.
- **TOP3 칩**: 테두리 `--border`, 글자 `--fg`, "한식 12" (숫자는 600). 색 점은 넣지 않는다. 지금은 메뉴 색을 글자색·테두리색으로 쓰고 있어서 고친다.
- **지도 메뉴 칩** (§5.5): 기본은 테두리 칩, 고른 칩은 `--fg` 채움 + `--bg` 글자.
- 칩 함수가 `LunchHome.tsx`와 `LunchMap.tsx`에 따로 있다. 칩 컴포넌트 하나로 합친다 (CLAUDE.md "같은 로직 두 번이면 뽑는다").

### 5.3 룰렛

- 결과 영역 높이를 고정해 돌 때 화면이 흔들리지 않게 한다.
- 결과는 20/700 `--fg` 글자. 지금은 메뉴 색을 글자색으로 써서 면·국밥이 흰 배경에서 거의 안 보인다.
- 멈춘 뒤 바로 가게 시트가 열린다 (지금 동작 유지).
- 움직임 줄이기 설정(`prefers-reduced-motion`)에서는 돌리지 않고 결과만 보여준다.

### 5.4 시트와 카드

두 가지로 나눈다.

| | 하단 시트 (`ShopSheet`) | 정보 카드 (지도 칸 선택) |
|---|---|---|
| 용도 | 결정하기 (할 일이 있음) | 칸 정보 보기 |
| 뒤 배경 | `--overlay`로 어둡게 | 그대로 |
| 위치 | 화면 아래에 붙음, 위쪽 모서리 16 | 아래에서 16 띄움, 모서리 12, 그림자 |
| 닫기 | ✕ 버튼, 배경 탭, Esc | 카드 탭, 다른 칸 탭 |
| 배경색 | `--surface` | `--surface` |

- 하단 시트에는 `role="dialog"`, `aria-modal`, 열릴 때 포커스 이동을 넣는다 (지금 없음).
- 최대 높이 80dvh, 넘치면 시트 안에서 스크롤한다.
- 시트 제목은 "한식 · 근처 가게"처럼 `--fg` 글자로 쓴다 (지금은 메뉴 이름만 메뉴 색).

### 5.5 지도 (메뉴 하나씩 보기)

**구성 (위에서 아래로)**
1. 제목 "오늘의 점심 지도" + 기준 날짜
2. 메뉴 칩 줄: 메뉴 10개, 가로 스크롤 한 줄. 고른 칩 1개만 채움
3. 지도: 고른 메뉴를 동네마다 얼마나 골랐는지 주황 3단계로 칠함
4. 범례: `표 적음` · `조금` · `보통` · `많이` 네 칸과 각 기준 숫자
5. 칸을 누르면 정보 카드 (§5.4): 칸 이름, 고른 메뉴 표 수, 그 칸의 오늘 TOP3

**처음 고른 메뉴**: 오늘 내가 결정한 메뉴가 있으면 그 메뉴, 없으면 오늘 전국 1위 메뉴. 고른 메뉴는 주소(`/map?menu=korean`)에 남겨서 공유하거나 뒤로 가기를 해도 유지한다.

**칸 칠하기**
- 그 칸의 오늘 전체 표가 5개 미만이면 `--map-empty` (지금 SPEC의 5표 기준 유지)
- 5개 이상이면 고른 메뉴의 값에 따라 `--map-1` ~ `--map-3`. 기준이 표 수인지 비율인지는 §9에서 정한다
- 동률 빗금은 없앤다. 메뉴 하나만 보니 동률이 생기지 않는다
- 경계선 `--map-stroke` 0.4px, 고른 칸은 `--fg` 2px
- 서울 자치구처럼 작은 칸은 375px에서 누르기 어렵다. 확대와 이동은 §9에 둔다

**바뀐 점**: 동네별 1위 메뉴는 지도에서 한눈에 못 본다. 대신 칸 정보 카드의 TOP3로 보여준다.

## 6. 상태 (로딩 · 비어 있음 · 오류)

모든 데이터 영역에 세 상태를 같이 만든다 (CLAUDE.md 코딩 규칙).

| 화면 | 로딩 | 비어 있음 | 오류 |
|---|---|---|---|
| 내 칸 | "찾는 중…" (버튼 안) | 위치 찾기 버튼 | "위치 권한이 거부되었습니다" → `--danger` + 다시 시도 |
| 가게 시트 | "가게 찾는 중…" | "근처에 결과가 없어요. 다른 메뉴를 골라보세요." | 오류 문구 + 다시 시도 버튼 (지금 없음) |
| 이걸로 결정 | "기록 중…" | — | **지금은 조용히 실패한다.** "기록하지 못했어요. 다시 눌러주세요."를 보여준다 |
| 지도 | 칸 모양을 `--map-empty`로 먼저 그림 (지금은 빈 화면) | "오늘 아직 한식 고른 사람이 없어요" (고른 메뉴 이름) | "지도를 불러오지 못했어요" + 다시 시도 |
| 메뉴 바꾸기 | 이전 지도를 옅게 둔 채 새로 칠함 (화면이 비지 않게) | 위 지도 비어 있음과 같음 | 이전 지도 유지 + "불러오지 못했어요" |
| 칸 정보 카드 | "불러오는 중…" | "오늘 아직 표가 없어요." | 비어 있음과 같은 문구 |

## 7. 말투

- 해요체, 짧게. 예: "오늘은 이미 결정했어요", "탭하면 닫혀요".
- 사람을 "동네 사람들", 지역을 "내 칸"·"우리 동네"로 부른다.
- 숫자는 사람 수로 말한다: "한식 고른 사람 12명".
- 오류는 무엇이 안 됐는지 + 다음에 할 일을 같이 쓴다.
- 이모지는 버튼 앞과 결정 완료(🎉)에만 쓴다.

## 9. 열린 질문

| 질문 | 선택지·추천 | 정할 때 |
|---|---|---|
| 진하기 기준 | A 고른 메뉴의 표 수 (지금 기준 5~9 / 10~29 / 30+) / B 그 칸에서 고른 메뉴가 차지하는 비율. **추천 B** — 표 수로 하면 사람이 많은 동네만 진해져서 "어디서 한식을 많이 먹었나"가 아니라 "어디에 사람이 많나"가 된다 | `/api/map` 바꾸기 전 |
| 비율로 할 때 단계 기준 | 예: 10% 미만 / 10~25% / 25%+. 실제 표가 쌓인 뒤 분포를 보고 정함 | 공개 전 |
| 지도 확대·이동 | A 없음 / B 시도 단위로 확대 / C 두 손가락 확대. **추천 B** (구현 단순, 작은 구 문제 해결) | 지도 사용 후 |
| 공유 이미지 | 공유 카드를 만들면 라이트 모드로 고정할지 | 공유 기능 만들 때 |

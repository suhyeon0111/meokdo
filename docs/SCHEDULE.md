## Week 1 — 결정 흐름 (사전 검증 병행)

### Day 1 · 리셋 + 셋업 + 카카오/경계 검증
- [ ] meokdo 잔존 코드 정리(인증·MapLibre·records 마이그레이션·검색 프록시 제거) — 코드 마이그레이션 계획 참조
- [ ] 카카오 **JS 키** 발급, 도메인 등록, services 라이브러리 로드
- [ ] **쿼터 확인**: 이 앱이 계정 첫 활성 앱인지(리스크 #3). 가게 검색은 메뉴 선택 후에만 호출하도록 설계
- [ ] 시군구 경계 GeoJSON ↔ 카카오 `coord2RegionCode` 코드 **매칭 확인**(2026-07 개편 포함, 리스크 #6)
- **DoD**: 실기기에서 위치 허용 → 내 시군구 코드가 잡힌다. 그 코드가 레포 경계 파일의 코드와 일치한다. 쿼터 대상 여부 기록.

### Day 2 · 내 칸 찾기 + 메뉴 10 + 룰렛
- [ ] 위치 허용 흐름 + 거부 시 시도→시군구 직접 선택(마지막 선택 localStorage)
- [ ] 메뉴 10종 상수/UI, 룰렛(가벼운 애니)
- **DoD**: 권한을 거부해도 시군구를 직접 골라 홈을 쓸 수 있다. 룰렛이 10종 중 하나를 고른다.

### Day 3 · 근처 가게 시트
- [ ] 메뉴 선택 → `keywordSearch`(현재 좌표, 거리순) → 가게 목록 시트 → 카카오맵 상세 링크
- [ ] 좌표·결과를 저장/전송하지 않음 확인
- **DoD**: 실기기에서 메뉴를 고르면 근처 가게가 1초 안팎으로 거리순으로 뜬다. 네트워크 탭에 좌표/가게가 우리 서버로 가지 않는다.

### Day 4 · 홈 + today API(목업) + 사전 검증 시작
- [ ] 홈 레이아웃(내 칸 이름 + TOP3 칩 + 메뉴/룰렛 + 지도 진입)
- [ ] `GET /api/today` 목업 데이터로 TOP3 표시
- [ ] 스레드 사전 검증 5일 1일차 게시
- **DoD**: 홈에서 내 칸 TOP3가 보인다(목업). 사전 검증 1일차 글이 올라갔고 결과를 기록 중.

## Week 2 — 투표와 지도

### Day 5 · DB + vote API
- [ ] 마이그레이션(vote_counts, event_counts, bump_vote/bump_event, RLS 전면차단)
- [ ] `POST /api/vote`(zod 화이트리스트, KST today, 방문구간) — service_role
- **DoD**: `/api/vote` 호출 시 해당 (오늘,칸,메뉴,구간) count가 1 증가한다. DB에 좌표·IP 컬럼이 없다.

### Day 6 · today/map API + 넘겨 보여주기
- [ ] `GET /api/today`(칸<5 → 시도 → 전국), `GET /api/map`(칸별 1위·표수·동률)
- [ ] 캐시 30~60s
- **DoD**: 표가 적은 칸에서 시도/전국 TOP3로 넘어간다. map API가 ≥5표 칸만 반환한다.

### Day 7 · 오늘의 점심 지도(SVG)
- [ ] d3-geo로 시군구 SVG, 1위 메뉴 색 + 3단계 진하기 + 동률 빗금 + 범례
- [ ] 칸 탭 → 해당 칸 TOP3
- **DoD**: 테스트 투표 100개를 넣으면 지도와 TOP3가 규칙대로 칠해진다. 범례가 항상 보인다.

### Day 8 · 결정 1표 + 남용 방지 1·2단계
- [ ] "이걸로 결정" → localStorage 하루 1회 + `POST /api/vote`
- [ ] IP 만료 카운터(Upstash) 레이트리밋, IP DB 미저장
- **DoD**: 같은 기기에서 두 번째 결정이 막힌다. 짧은 시간 다량 요청이 429로 제한된다. DB에 IP가 없다.

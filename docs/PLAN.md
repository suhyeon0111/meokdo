## 2. 위험 검증 우선 — 첫 3일 (스파이크)

### Day 1 (≈4h) — 셋업 + 카카오 검색 프록시 + 쿼터 확인
- Next 16 앱, TS, Supabase 프로젝트, **카카오 개발자 앱(로컬 REST 검색용)** 등록, env, Vercel 배포 1회.
- `GET /api/places/search` 프록시로 카카오 키워드 검색이 서버에서 200 수신.
- **쿼터 확인**: 이 앱이 계정의 **첫 활성 앱**인지(아니면 새 계정). 지도 타일 미사용이라 검색 쿼터만 해당. → DECISIONS #3.
- DoD: 빈 페이지가 Vercel URL에 뜬다. "강남 파스타" 검색 시 후보 목록(이름·주소·좌표)이 서버 프록시로 반환된다. 쿼터 대상 여부를 기록.

### Day 2 (≈6h) — 리스크 (a) 폴리곤 렌더 성능
- SGIS 시군구 원본(2025-06-30) → mapshaper 화면용 GeoJSON → **MapLibre에 polygon choropleth** 렌더(배경 타일 없이).
- 모바일(실기기/스로틀) 첫 로드·팬/줌 FPS·파일 크기 측정.
- DoD: 전국 시군구가 모바일에서 끊김 없이 색칠·팬/줌된다. 화면용 gzip 크기를 §7 목표와 비교 기록. 초과 시 완화안 1줄 결정.

### Day 3 (≈6h) — 리스크 (b) 판정 정확도 (+2026-07 개편 영역)
- 판정용 GeoJSON + Turf bbox prefilter. **경계·일반구 + 인천·전남광주 개편 영역 테스트 좌표 50개**(정답 라벨) → `region.test.ts`.
- 인천 2군·9구 / 전남광주통합특별시 수동 패치 임시본으로 판정 검증.
- DoD: 50개 중 오판정 0건(또는 원인이 데이터 자체임을 규명). 일반구가 구 단위로 갈린다. 개편 영역이 2026-07 기준으로 판정된다.

> 3일 안에 실패 시 전환: (a) → 광역 집계 폴백, (b) → PostGIS `ST_Contains`, 쿼터 → 새 계정. 경계 패치가 Day 3 안에 안 끝나면 §4 "패치 범위 축소"로.
